01 — Banco de Dados

Conexão Única vs. Separação Leitura/Escrita

Atualmente o sistema utiliza uma única string de conexão para leitura e escrita. O que muda se segregarmos?

🔗 Conexão Única (Modelo Atual)

Uma só connection string para todas as operações (GET, POST, PUT, DELETE).

  • Simplicidade: Apenas um DbContext registrado no DI.
  • Consistência Imediata: Um dado salvo no POST é lido imediatamente no GET seguinte.
  • Gargalo: Relatórios pesados ou paginações em massa consomem recursos do mesmo servidor que processa vendas/cadastros.

⚡ Conexões Separadas (Leitura vs Escrita)

Conexão de Escrita (Master) + Conexão de Leitura (Read Replica).

  • Desempenho: Consultas pesadas (grids, relatórios) vão para o nó de leitura sem travar a escrita.
  • Escalabilidade: Pode-se adicionar 2 ou 3 réplicas de leitura para suprir acessos simultâneos.
  • Cuidado (Consistência Eventual): Pode haver um delay de milissegundos na replicação.
Critério Conexão Única (Atual) Separação Leitura / Escrita (CQRS Leve)
Complexidade de Código Mínima (1 DbContext) Média (2 DbContexts ou Query Splitting)
Alívio de Carga no Banco Nenhum Alto (consultas vão para réplicas)
Consistência de Dados Imediata (ACID total) Eventual (delay de replicação de ms)
Uso de AsNoTracking() Manual em cada query Nativo no DbContext de Leitura
Recomendado para ERP? Fases iniciais / Menor carga Ideal para alto volume de dados
💡
Como implementar de forma limpa no .NET 10 sem complicar
Você não precisa reescrever o sistema. Basta registrar dois DbContexts (ou injetar duas connection strings):
• AcessoGlobalWriteDbContext — para operações que alteram estado (POST/PUT/DELETE).
• AcessoGlobalReadDbContext — configurado com QueryTrackingBehavior.NoTracking apontando para a réplica de leitura.
02 — Auditoria de Código

Clean Architecture, SOLID & .NET 10 no Versatus.Net8

Analisamos a estrutura do código C# atualmente no repositório para verificar a aderência às boas práticas de arquitetura e linguagens modernas.

✓

1. Clean Architecture (Arquitetura em Camadas) — CONFORME

O projeto está estruturado em módulos independentes (Versatus.AcessoGlobal, Versatus.GestaoTributo, Versatus.Framework, Versatus.WebAPI), segregando claramente:

• Domain: Entidades POCO puras, Interfaces, Services de Negócio, Result Pattern.
• Infrastructure: DbContext, Mappings Fluent API EF Core, Implementação de Repositórios.
• Api: Controllers finos recebendo DTOs e retornando IActionResults.
• Framework: Utilitários compartilhados, validação e abstração de repositório.
✓

2. Princípios SOLID — CONFORME

Aplicação exemplar dos 5 princípios:

• SRP (Single Responsibility): Controllers só expõem HTTP; Services contêm regras de negócio; Repositories tratam de acesso a dados.
• OCP (Open/Closed): Fluent Mappings modulares via ApplyConfigurationsFromAssembly.
• DIP (Dependency Inversion): Injeção de dependência via interfaces (IEntidadeService, IRepositorio<T>) em todos os controllers e serviços.
✓

3. Clean Code & Result Pattern — CONFORME

Em conformidade estrita com as diretrizes do projeto: proibido lançar exceções para erros de negócio esperados. Uso de Result<T> funcional encapsulando erros de validação estruturados.

var result = await _entidadeService.SalvarCompletoAsync(dto);
if (!result.IsSuccess) return BadRequest(new { message = result.Errors[0].Mensagem });
✓

4. Recurso Modernos do C# 12/13 / .NET 10 — CONFORME

O código utiliza os recursos mais modernos da plataforma .NET:

• File-Scoped Namespaces: namespace Versatus.AcessoGlobal.Api.Controllers; (código limpo sem aninhamento).
• Nullable Reference Types: Ativados para evitar NullReferenceException em tempo de compilação.
• EF Core Conventions: Mapeamentos globais elegantes como configurationBuilder.Properties<bool>().HaveConversion<short>() para tratar especificidades do SQL Server 2008 legado sem poluir entidades.
Conclusão Geral da Auditoria

O código do backend está excelente. A separação de leitura/escrita é recomendada para o futuro.

O projeto Versatus.Net8 segue rigorosamente os padrões de Clean Architecture, SOLID, Clean Code e recursos modernos do .NET 10. O domínio está protegido e desassociado de dependências de infraestrutura.

Recomendação para Conexões: Mantenha a conexão única durante a migração dos formulários legados. Assim que a aplicação estiver em produção com volume de acessos, introduza a conexão de leitura com AsNoTracking() no AcessoGlobalReadDbContext para acelerar pesquisas e relatórios sem impactar as gravações.
